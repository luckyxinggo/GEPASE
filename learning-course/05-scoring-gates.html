COURSE 05 · SCORING & GATES

“变好”不是一个模糊总分，而是一组目标、保护线和严格接纳规则

GEPASE 保留六维 TaskScoreVector 和每个 case 的配对差值。候选先通过结构与安全，再通过 train 筛选，最后才解锁 held-out validation；平均值上升也不能越过类别回归底线。

预计 55 分钟含配对统计含真实拒绝案例
01
SIX DIMENSIONS

TaskScoreVector 的每一维在保护什么？

task_correctness

任务事实与硬性要求是否正确，例如 GIF 尺寸、帧数和指定内容。

output_quality

成品是否完整、专业、易用、格式得体；弥补断言难覆盖的质量。

skill_gain

相对 no-skill 或 original 的实际增益，而不是候选自己的绝对分。

reliability

是否稳定执行、少失败、少自相矛盾，跨 case 是否可靠。

efficiency

工具调用、上下文读取、token、时间等是否合理；不是越少越好，而是避免无谓浪费。

package_quality

文件组织、引用、可维护性、安全和结构是否健康，防止只追任务分而让包退化。

为什么不自动压成一个 reward？

权重会隐藏价值判断：例如平均质量略升，却让可靠性大降。Core 保留向量和 task-level feedback；具体 Gate 明确写出主目标、保护目标与阈值。

实际 schema 对应的六维结构
TaskScoreVector(
    task_correctness=0.86,
    output_quality=0.82,
    skill_gain=+0.12,
    reliability=0.90,
    efficiency=0.74,
    package_quality=0.88,
)
02
PAIR FIRST, AGGREGATE LATER

先算每题差值，再汇总；不要比较两批陌生均值

CaseOriginalCandidatePaired delta解释
A · 文本动画0.620.78+0.16显著改善
B · 循环过渡0.760.82+0.06小幅改善
C · emoji 动画0.880.80−0.08局部回归
mean_delta = (0.16 + 0.06 − 0.08) / 3 = +0.0467

总均值是正的，但 category floor 如果规定任何重要类别不得低于 −0.05，这个候选仍应被拒绝。它避免多数简单任务掩盖一个重要能力退化。

统计不只是 p-value

胜负计数

候选在多少配对 case 上胜、平、负，避免均值由单个极端样本推动。

Bootstrap CI

对 case-level delta 重采样，估计平均增益的不确定区间。

Variance policy

样本少或波动大时标记 inconclusive，而不是强行宣布胜利。

03
FROM EVIDENCE TO SEARCH SIGNAL

六维分数怎样由证据构造，又怎样交给 GEPA？

TaskScoreVector 不是让某个 LLM 随手输出六个小数。每一维都要能追溯到确定性检查、独立评分、配对比较或 Package 诊断。

维度主要证据来源GIF case 示例交给搜索器的附加反馈
task_correctnessE3 assertions + 事实核验尺寸、格式、动画帧、体积是否满足逐项通过/失败和真实测量值
output_qualityIndependent Grader + Comparator循环自然、文字可读、层次完整rubric 理由与匿名 A/B 偏好
skill_gain同 case paired deltacandidate 相对 original/no-skill 的增益参考身份、差值和胜负
reliabilitytyped failure + 跨重复执行timeout、脚本错误、声明与产物矛盾失败类型、发生阶段和频率
efficiencyusage/timing/trace无关文件读取、重复工具调用、耗时实际访问节点与资源消耗
package_qualityE0 + graph diagnostics引用断裂、组织退化、新依赖未声明诊断节点、severity 与 blast radius

第一层：数据层。保存断言证据、rubric 分项、比较理由、trace 与 Package diagnostics，不急着压缩。

第二层：任务向量层。按冻结 scoring policy 得到每个 case、每个 variant 的六维向量，并计算 paired delta。

第三层：搜索层。GEPA 可以用目标聚合做候选筛选，但 Reflection 同时读取 task-level feedback 和轨迹，知道“为什么”而不只有“多少分”。

第四层：部署层。GEPASE Gate 重新使用原始向量、类别/风险 floor 和 held-out split；搜索中的局部优势不能自动换成部署资格。

交给下一章 GEPA 的不是一个 reward

输入是候选逐 task/逐 objective 的成绩、完整 EvaluationRecord、失败反馈和预算状态。下一章会先学习官方 GEPA 如何消费这些高带宽信号，再回到 GEPASE。

04
GATE LADDER

Gate 0–4 是逐层升级的证据门槛

Gate 0schema、Patch 结构、前置条件
Gate 1静态、安全、语法与 Package 健康
Gate 2train/minibatch 至少一个目标严格改善且保护目标不越界
Gate 3held-out validation 严格改善，类别/风险 floor 全过
Gate 4进入 deployable frontier 与持久化报告
完全等分怎么处理？

完全等分不是“没有坏所以接受”，而是 reject 或 inconclusive。搜索池可以保存分析历史，但 deployable frontier 必须由严格改善支撑。

为什么 validation 只能在 train 之后看？

如果每次 Patch 都看 validation 再决定下一步，validation 就逐渐变成训练集。GEPASE 先用 train 反馈搜索，只有 train-admitted 候选才进入 Gate 3；验证任务和评分契约冻结。

本章面试问答

为什么 skill_gain 还要作为独立维度？
绝对质量高可能只是 Agent 本身强；skill_gain 通过 paired reference 回答加入或修改 Skill 后是否真的增加能力。它与 task_correctness 关注点不同。
样本只有 3 个 validation case，能证明什么？
只能证明这个公开 canary 的冻结小样本上出现一致增益，不能推断普适性。应同时报告 3/3 wins、平均 delta、bootstrap CI 和样本限制，并通过后续 Skill 扩充外部有效性。
为什么平均提升还要设置 category floor？
多目标平均会掩盖关键局部回归。类别和风险 floor 把“哪些能力不能退化”变成预注册契约，尤其适用于安全、高风险或核心用例。

本章结论

  • 六维向量保留正确性、质量、增益、稳定、效率与包健康。
  • paired delta 是归因 Skill 增益的基础。
  • 严格提升与 held-out Gate 阻止等分和过拟合候选进入部署前沿。
  • 平均分不能覆盖类别回归底线。
