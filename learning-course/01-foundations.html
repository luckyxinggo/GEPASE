01
HEURISTIC LEARNING

不更新模型权重，也可以“学习”

传统训练修改模型参数；启发式学习直接修改模型外部可读的规则、代码、记忆和上下文。

类比

棋手的大脑不变，但你可以更新他的开局手册、复盘笔记和计算工具。下次行动策略因此改变，这也是一种学习，只是被更新的状态在模型之外。

冻结的 Agent 模型 M + 可更新的 Package θ → 行为策略 π(a | task, θ)

环境反馈

真实任务产物、错误、trace、grader 与 comparator 结论。

显式编辑

对 Markdown、代码、参考文件或配置实施可审查 Patch。

下一轮行为

Agent 读取新 Package 后改变规划、工具调用和产物质量。

GEPASE 因而把 视为参数 θ，但这里的“训练”不涉及梯度和模型权重。

一次“无梯度学习”必须同时具备四个条件

可变状态

必须明确哪些外部内容允许更新。GEPASE 中是不可变父快照派生出的 PackageCandidate，而不是直接改模型或用户原目录。

环境反馈

反馈必须来自实际任务行为：原生产物、工具轨迹、错误、独立评分和对照差值，而不是模型对自己的静态观感。

编辑算子

系统需要知道如何从反馈产生新的策略状态。这里是带目标节点、前置条件和预算的 typed PackagePatch。

接纳规则

修改不能因为“看起来合理”就生效；必须通过结构、安全、train 和 held-out validation 的冻结 Gate。

t

第 t 轮有策略状态 θₜ，Agent 在任务环境中执行，得到轨迹 τₜ 和任务反馈 Fₜ。

μ

mutation operator 根据 (θₜ, τₜ, Fₜ) 提出修改 Δθₜ，形成候选 θ′=apply(θₜ, Δθₜ)。

G

Gate 在冻结任务上判断 G(θ′, θₜ)；通过才写入候选前沿，失败则进入 rejected memory。

03
ANTHROPIC SKILL-CREATOR

skill-creator 的核心不是生成 SKILL.md，而是把“触发”和“做事”拆成两种可观察实验

先分析 Skill 能力边界

识别该 Skill 解决哪些用户意图、需要哪些输入、应交付什么原生产物，以及什么相似请求不该触发。

生成 activation / trigger queries

正例、负例和近边界 query 用于检查 description/metadata；失败通常修改触发描述，不应混入功能分。

设计 functional tasks

让独立 Agent 真正使用 Skill 完成任务，保存 transcript 和 output，而不是让它解释“我会怎么做”。

独立 grader 与 blind comparison

评分角色读取任务与产物，A/B comparator 不知道哪个输出来自新版本，减少候选身份偏见。

Analyzer 解释胜负，再迭代 Skill

分析不是最终分数，而是把失败转成可编辑建议；下一轮仍需重新执行与比较。

GEPASE 直接保留

Trigger/Functional 分轨、真实产物、with-skill/no-skill 对照、独立角色、匿名 comparator、Analyzer 读取证据。

GEPASE 进一步加严

EvalPlanDraft → 自动检查 → 中文人工 review → frozen hash；角色用 typed WorkItem/Submission；Core 拥有 ledger、cache、candidate 和 Gate。

继续学习：课程会在 EvalPlan 章节 展开出题与人工审核，在 真实 Agent 评测章节 展开角色可见性。参考 Anthropic skill-creator 与 官方介绍。
04
MICROSOFT SKILLOPT

SkillOpt 给 GEPASE 的最重要约束：修改是“候选编辑”，不是直接写回正式 Skill

从失败例子生成 bounded edits

优化器用 add/delete/replace 形式表达有限修改，避免每轮全量重写导致不可比较。

在 selection/train 数据上评估编辑

只有产生可测改进的编辑才有资格继续；完全等分不能为了“候选数量”被包装成成功。

在 held-out 数据上做严格选择

修改必须泛化到未参与产生它的任务，保护原有能力；否则即使 train 很好也拒绝。

把 rejected edits 变成负向记忆

保存编辑内容、触发的回归和拒绝理由，后续 proposer 避免重复犯错。

从 SkillOpt 风格编辑到 GEPASE typed PackagePatch
# 单文档层面的 bounded edit 直觉
edit = Replace(old_block="…", new_block="…")

# GEPASE 还要求文件/节点身份、父快照和前置条件
patch = PackagePatch(
    parent_candidate_id="candidate-A",
    operations=[ReplaceMarkdownBlock(
        target_node_id="SKILL.md#verification",
        expected_content_hash="sha256:old…",
        replacement="…",
    )],
    edit_budget={"max_files": 1, "max_ops": 1},
)
不能机械照搬的地方

一个 Package edit 可能改变 Python 函数、reference、frontmatter 或资产引用。GEPASE 必须在应用后重建 IR/Graph、计算 dependency closure 和 blast radius；这超出了单文档 add/delete/replace。

继续学习：图引导 Patch 章节 会逐项解释七类 PackagePatch 操作、precondition、atomic apply 与 rollback。参考 SkillOpt 官方项目。
05
DARWIN SKILL

Darwin skill 提供的是“进化工作流”直觉：任何改进都要留下可回退历史

执行任务在环境里暴露真实缺陷
反思失败把证据变成修订理由
生成新版本不覆盖旧版本
独立判断新版本是否真的更好
Git ratchet只让通过者推进基线
Human checkpoint高影响变更可人工介入

GEPASE 借鉴 lineage

每个 child 记录父代、Patch、图差异和 Gate，形成候选 DAG。

GEPASE 加入 paired evidence

不是由同一个 Agent 自己宣布改进，而是同 case 对照、独立 grader/comparator。

GEPASE 加入 strict frontier

train pool 与 deployable frontier 分开，validation 回归不会推进正式版本。

继续学习：在 GEPASE 搜索适配 看 branch/lineage，在 真实 canary 看 accepted/rejected 历史。参考 Darwin skill 官方仓库。
06
GEPA PREVIEW

GEPA 为什么不只保留一个总分最高的候选？

GEPA 的核心价值不是“让 LLM 随便反思”，而是保留任务级轨迹、结构化反馈和不同目标上的局部优势。本节只建立地图，后面有两章完整推导。

选择候选从 Pareto 池选父代
选择任务找有失败信息或优化价值的 case
读取轨迹不只看一个 reward
生成反思解释失败和修改依据
产生 mutation修改文本组件或 Package 节点
评测入池保留局部优势

Pareto 用一个两目标例子理解

候选GIF 视觉质量文件体积稳定性关系
A0.900.60A 擅长视觉
B0.780.92B 擅长稳定
C0.700.55C 被 A 完全支配

A 和 B 互不支配，可能共同进入 ；C 在两个目标上都不如 A，没有保留必要。多父合并可以尝试把 A、B 的互补改进组合起来，但必须重新过 Gate。

GEPASE 没有从头复刻 GEPA

项目锁定并依赖 gepa==0.1.4，在外部增加 PackageCandidate、TaskScoreVector、图选择器、PackagePatch、验证门禁与 Package-aware merge。

进入 GEPA 深入章节学习官方 candidate、Adapter、EvaluationBatch、九步 reflective mutation、GEPAState、cache、merge，以及它与 GEPASE held-out Gate 的差异。→ 进入 Pareto 推导实验室从数学支配关系开始，拖动候选分数，再学习 GEPA instance/objective/hybrid/cartesian frontier 与频次抽样。→

CODE CONNECTION

思想怎样落进实际类型？

概念化伪代码 · 对应 Core 主链
# 模型不训练，Package 才是候选状态
parent = pool.select_pareto_parent(task_feedback)

# 轨迹 + grader + graph slice 形成可执行反思
insight = analyzer.reflect(parent, failed_cases, package_graph)

# 输出不是整包自由重写，而是结构化补丁
patch = proposer.propose(insight, bounded_scope=True)
child = applier.apply_atomically(parent, patch)

# train 负责搜索，held-out 负责最终接纳
if gates.train_pass(child) and gates.validation_strictly_improves(child):
    pool.add_deployable(child)
else:
    rejected_memory.remember(patch)

为什么“反思写得很有道理”仍不足以接纳候选？

本章面试问答

为什么选择 GEPA 而不是直接做强化学习？
目标状态是可读、可编辑的文本与代码 Package，任务反馈也包含自然语言轨迹。GEPA 式反思能直接利用这些高带宽反馈，同时避免模型权重训练成本；它还保留多目标与任务级局部优势。
GEPASE 的创新是否只是“拼项目”？
应诚实称为系统性组合创新。价值不在重新发明每个算法，而在把真实 Agent 评测、Package 级 IR/Graph、typed Patch、GEPA/Pareto 和 strict held-out Gate 串成一个边界清晰、可复现的 Core，并用真实 canary 验证闭环。
Pareto 会不会让候选池无限增长？
不会把所有候选都保留。被支配候选可淘汰，另外还有预算、父代选择和 Gate；工程上必须限制池规模与评测成本。

本章结论

  • 外部 Package 是策略状态，反馈驱动显式编辑。
  • GEPA 负责反思式多目标搜索，不替代评测和 Gate。
  • 其他参考项目分别补充评测、有界修改和工程历史。
