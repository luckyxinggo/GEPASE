01
DOMINANCE FROM FIRST PRINCIPLES

支配关系只需要两条规则

假设所有目标都已经转换成“越大越好”。候选 x 的目标向量是 f(x)=(f₁(x), …, fₘ(x))。

x ≻ y　⇔　(∀j, fⱼ(x) ≥ fⱼ(y))　且　(∃k, fₖ(x) > fₖ(y))
∀

所有目标不差：x 在每一维都至少和 y 一样好。

∃

至少一维更好：如果每一维都相等，只是 tie，不叫严格支配。

F

Pareto front：集合中没有被其他候选支配的所有候选。它通常不止一个点。

类比

选电脑时只看“性能”和“续航”：一台电脑性能、续航都更高，就支配另一台；如果一台性能强、一台续航长，两者互不支配，选择取决于偏好，算法不该过早删掉其中任何一个。

成本目标要先改方向

如果 token、时延、价格是越小越好，应变成 efficiency = normalize(−cost) 或明确用 minimization dominance。不能把“输出质量越大越好”和“时延越小越好”直接放进同一 ≥ 公式。

03
HOW TO COMPUTE A FRONT

最朴素的 Pareto 算法如何实现？

适合小候选池的 O(n²·m) 伪代码
def dominates(a, b):
    # 所有维度至少不差，并且至少一维严格更好
    no_worse = all(x >= y for x, y in zip(a.objectives, b.objectives))
    strictly_better = any(x > y for x, y in zip(a.objectives, b.objectives))
    return no_worse and strictly_better

def pareto_front(candidates):
    front = []
    for candidate in candidates:
        dominated = any(
            other.id != candidate.id and dominates(other, candidate)
            for other in candidates
        )
        if not dominated:
            front.append(candidate)
    return front

时间复杂度

n 个候选两两比较，每次看 m 个目标：O(n²m)。GEPASE 当前候选少，清晰比复杂数据结构更重要。

相等分数

完全相等不构成严格支配；可以都留，也可以用 hash/成本/年龄做确定性去重。

浮点误差

真实系统通常用 epsilon：差异小于阈值视为相等，避免噪声制造虚假前沿。

目标越多，前沿可能越大

高维时很多点互不支配，Pareto 本身不再足够筛选。需要 budget、Top-K、epsilon dominance、保护目标、采样策略或二阶段 Gate。GEPASE 不因使用 Pareto 就无限保留候选。

04
GEPA'S PER-KEY FRONTIER

GEPA 0.1.4 的“Pareto”还有一层特殊含义：为每个 key 保存冠军

官方 GEPAState 不只维护一个“所有目标组成的向量前沿”，还维护 frontier key → 达到该 key 最佳分数的 candidate set。key 的定义由 frontier_type 决定。

instance：每个 validation example 的冠军

key 是 val_id。如果 A 在 T1 最好、B 在 T2 最好，就得到 {T1:{A}, T2:{B}}。最直接保留 task-level local advantage。

objective：每个目标聚合值的冠军

先对各 example 的 objective score 聚合，再记录 {correctness:{A}, efficiency:{B}}。要求 Adapter 返回 objective_scores。

hybrid：instance 与 objective key 的并集

同时保留某题冠军和某目标冠军。候选可能因为任意一种局部优势进入 mapping。

cartesian：每个 (example, objective) 的冠军

key 变成 (T1, correctness)、(T1, efficiency) 等，粒度最细，mapping 也最大。

一个 per-instance 手算例子

候选T1T2T3平均
A0.950.600.720.757
B0.750.920.700.790
C0.700.700.680.693
D0.820.840.940.867
instance mapping = { T1:{A}, T2:{B}, T3:{D} }

D 是 aggregate current best，但 A、B 仍各覆盖一个 D 没拿到的 key。C 不在任何 key 的冠军集合里，无法提供 local advantage。

这和标准二维 Pareto front 不完全一样

标准 Pareto 比较完整 objective vector；GEPA per-key mapping 直接记录每个 example/objective 的 argmax。官方工具随后做覆盖意义上的 dominated-program removal，再按保留候选覆盖 key 的频次抽样。理解这层差异，才能准确读 ParetoCandidateSelector。

05
FROM MAPPING TO PARENT SAMPLING

ParetoCandidateSelector 怎样选一个父代？

统计每个 candidate 出现在哪些 frontier keys

例如 A 覆盖 T1、quality，B 覆盖 T2，D 覆盖 T3、reliability。

删除覆盖意义上冗余的 candidate

如果 y 出现的每一个 front 都有其他候选覆盖，y 可以被移除；实现迭代处理，且用 aggregate scores 辅助稳定顺序。

按剩余候选的 key 覆盖频次构造 sampling list

A 覆盖 2 个 key 就出现两次，B 覆盖 1 个 key出现一次，D 覆盖 2 个 key出现两次。

用有 seed 的 RNG 抽样

这不是永远选 aggregate best，而是让覆盖更多局部优势的候选更常成为父代，同时保持可复现探索。

官方选择逻辑的教学化简
mapping = {
    "T1": {"A"},
    "T2": {"B"},
    "T3": {"D"},
    "quality": {"A"},
    "reliability": {"D"},
}
sampling_list = ["A", "A", "B", "D", "D"]
parent = seeded_rng.choice(sampling_list)

因此“Pareto 选择”不等于“均匀随机选前沿成员”，也不等于“只选当前均分最高者”。项目同时保存 pareto_selected_id 和 current_best_id，正是为了让两种视角可审计。

06
PARETO INSIDE GEPASE

GEPASE 如何使用 Pareto，又在哪些地方加了更严格边界？

层次保存什么能否部署
GEPA train statecandidate 的 task/objective 局部优势与父代选择信息不能，仅用于搜索
Evolution poolcandidate identity、lineage、Patch、train admission、merge eligibility不能自动部署
Deployable frontier通过 Gate 0–3、held-out 严格改善且保护目标不过界的 candidate可以作为部署输出
Pareto 成员不等于“好版本”

候选可能只在一个 train case 上局部领先，却在 frozen validation 上回归。Pareto 的职责是保留搜索可能性；strict Gate 的职责是决定是否值得部署。两者不能合并成一个状态。

为什么多父 merge 与 Pareto 天然相关？

如果 A 因 T1/quality 留在 front，B 因 T2/efficiency 留在 front，它们的互补优势提供 merge 动机。但 merge 必须满足同 Package、共同 lineage root、依赖闭包和冲突契约；child 的分数从零重新测量。

本章面试问答

请给出 Pareto 支配的严格定义
在全部目标都最大化时，x 支配 y 当且仅当 x 在所有目标上不差于 y，并且至少一个目标严格优于 y。Pareto front 是不被集合中其他候选支配的点。
GEPA 的 per-instance frontier 与标准多目标 Pareto 有何不同？
标准 Pareto 对候选的目标向量做全维支配比较；GEPA instance frontier 对每个 val example 保存达到该题最高分的 candidate set，再对跨 key 覆盖做冗余删除与频次抽样。objective/hybrid/cartesian 会改变 key 的定义。
为什么不能把 Pareto front 直接当 deployable frontier？
它表达搜索中的局部优势，可能来自 train 或引擎 valset，并不保证 frozen held-out 泛化、结构安全和保护目标。GEPASE 另设 Gate 0–3 与 deployment held-out。
目标维度很多时 Pareto 有什么问题？
维度越高，互不支配点越多，front 可能膨胀。需要预算、epsilon、Top-K、key coverage、保护目标或二阶段选择，不能仅依赖 nondominance。

本章必须真正掌握的五点

  • 支配是“所有维度不差且至少一维严格更好”；相等不是严格支配。
  • 标准 Pareto front 保存未被全面击败的候选，但不自动给出最终选择。
  • GEPA 按 instance/objective/hybrid/cartesian 定义 frontier keys 和冠军 mapping。
  • ParetoCandidateSelector 在去除覆盖冗余后，按候选覆盖 key 的频次抽样。
  • GEPASE 的 train Pareto pool 与 deployable frontier 必须严格分开。
