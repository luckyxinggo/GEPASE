先把 GEPASE 看成一台“让 Skill 接受真实考试并持续改进”的机器

这不是论文式术语堆砌，也不是从代码目录倒推用途。本课先用一个贯穿全程的例子回答四件事：为什么要做、它优化什么、证据从哪里来、什么修改才算真正被接受。

01
THE STARTING POINT

项目从哪个真实问题出发？

Agent Skill 很容易“写到能运行”，却很难知道距离“稳定、好用、不会退化”还有多远。

一句人话

你给新员工写了一本工作手册。手册能被打开，不代表员工能把工作做好；今天补一条、明天再补一条，也可能把手册补成互相冲突的杂物堆。GEPASE 做的是：安排真实工作、保留证据、定位问题、做小范围修改，再用没见过的工作复查。

能运行 ≠ 好用

脚本没有报错、文件存在，只能说明最低工程条件成立；它不能证明内容正确、产物专业或 Skill 带来增益。

持续加字 ≠ 持续进化

只追加 SKILL.md 会引入重复规则、冲突指令和过长上下文，也忽略 references、scripts 与 assets。

一次成功 ≠ 稳定提升

模型有随机性，任务也有难度差异。必须做同轮配对比较，并用冻结验证集检查泛化。

本项目当前最重要的诚实边界

“代码已实现”“工程机制通过测试”“算法效果已经验证”是三件不同的事。GEPASE 已完成大量 Core 与一次公开 canary 闭环；它不宣称已经对所有 Skill 普遍有效。

02
WHAT IS OPTIMIZED

优化对象不是一段 Prompt，而是完整 Skill Package

点击目录项，观察每种文件在同一个任务里承担什么责任。

SKILL.md：入口与工作协议

写明什么时候使用 Skill、总体流程、约束和渐进披露入口。它重要，但不是全部。

references：按需加载的专业知识

例如 GIF 视觉原则、压缩限制、示例解释。把细节放这里可以避免主文件无限膨胀。

scripts：可重复执行的确定性能力

例如渲染、检查尺寸、计算帧率。脚本 bug 会直接影响最终产物，不能靠改 Prompt 掩盖。

assets：任务使用的非文本资源

模板、图标、示例图片或字体。资产可能被错误引用、缺失或与说明不一致。

metadata/runtime：发现与执行条件

description 决定是否触发，依赖和运行配置决定脚本能否在目标环境真正执行。

因此， 是冻结模型之外的“可训练状态”；修改可能落在 Markdown、代码、资产或配置上，文件之间的依赖也必须一起考虑。

03
WHO OWNS WHAT

完整架构：Core 管状态与裁决，Agent Host 负责真实工作

最关键的边界是：GEPASE 不再自研第二套通用 Agent Runtime，也不把候选池和评分逻辑藏进编排 Skill。

默认 Agent-native

普通使用不强制额外 API Key。Core 导出 ，宿主调用隔离 Agent，再提交结构化证据。

可选 Headless Provider

OpenAI-compatible 等模型 API 可以替换某些角色后端，用于自动化或模型对比，但不改变 Core 的权限与数据契约。

Orchestrator 是薄层

.agents/skills/gepase-orchestrator/ 只领取、分发和提交工作；不能拥有评分、候选池、GEPA 或 Gate。

THE RECURRING EXAMPLE

全课会反复使用同一个 loop-sparkles-006 GIF case

你会依次看到：它怎样从 Package 能力变成 EvalPlan case；怎样由三个隔离 variant 生成 GIF；怎样形成 TaskScoreVector 与失败轨迹；怎样触发 GEPA reflection 和图节点选择；怎样成为 PackagePatch；最后怎样在 frozen validation 中证明或否定修改。

这样每个算法出现时都有“它正在解决上一环节留下的哪个具体问题”，不会突然开始一个无上下文章节。

本章面试问答

请用 30 秒介绍 GEPASE
建议回答：GEPASE 是一个独立 Python Core 驱动的 Agent Skill Package 进化框架。它让真实 Agent 在同轮隔离环境中执行 with-skill 与 baseline 任务，保留原生产物和轨迹；再通过 GEPA 式反思与 Pareto 搜索，结合 Package Graph 定位文件，生成有界 typed Patch。候选只有在结构、安全、训练和 held-out validation 上严格通过，才进入可部署前沿。
它和“让 LLM 重写 SKILL.md”最大的区别是什么？
优化对象、反馈和接纳规则都不同：它优化完整 Package；反馈来自真实任务与独立评审；修改是带前置条件和影响分析的结构化 Patch；接纳需要严格验证，不凭一次 LLM 自评。
为什么不自研通用 Agent Runtime？
异构业务 Skill 的工具和环境差异很大。让成熟 Agent Host 负责执行，可以聚焦 GEPASE 的核心贡献：评测契约、证据、图、搜索、Patch、Gate 和可复现状态。

这一课只需要记住四句话

  • 优化的是完整 Skill Package，不只是一段 Prompt。
  • 真实 Agent Host 负责做事，GEPASE Core 负责出题、记证据、搜索和裁决。
  • 功能效果必须来自真实任务原生产物，不能由框架合成统一业务结果。
  • 候选“能跑”不等于“变好”；held-out 严格提升才有资格被接纳。
